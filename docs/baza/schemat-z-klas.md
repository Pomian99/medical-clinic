# Schemat wygenerowany z klas

## DDL z logu

Z logu aplikacji (`spring.jpa.show-sql=true`):

```text
Hibernate: create table patients (id bigint generated by default as identity, birthday date, email varchar(255) not null, first_name varchar(100) not null, id_card_no varchar(20) not null, last_name varchar(100) not null, password varchar(255) not null, phone_number varchar(20) not null, primary key (id))
```

## Skąd się wzięła każda kolumna

| Pole | Kolumna | Typ | Skąd |
|---|---|---|---|
| `id` | `id` | bigint | `@Id`, `@GeneratedValue(strategy = IDENTITY)`; `bigint` z typu `Long` |
| `email` | `email` | character varying(255) | `@Column(nullable = false, unique = true)` |
| `password` | `password` | character varying(255) | `@Column(nullable = false)` |
| `idCardNo` | `id_card_no` | character varying(20) | `@Column(nullable = false, unique = true, length = 20)` |
| `firstName` | `first_name` | character varying(100) | `@Column(nullable = false, length = 100)` |
| `lastName` | `last_name` | character varying(100) | `@Column(nullable = false, length = 100)` |
| `phoneNumber` | `phone_number` | character varying(20) | `@Column(nullable = false, length = 20)` |
| `birthday` | `birthday` | date | brak adnotacji: `date` z typu `LocalDate`, `null` dozwolony domyślnie |


- **Nazwy w snake_case:** Spring Boot ustawia Hibernate'owi strategię nazw
  `PhysicalNamingStrategySnakeCaseImpl`, która zamienia `idCardNo` na `id_card_no`.
  Nazwa tabeli pochodzi z `@Table(name = "patients")`, bez niej byłoby `patient`.
- **`varchar(255)`:** `@Column` ma domyślnie `length = 255`, więc tyle dostaje każde pole
  `String` bez podanego `length` (`email`, `password`).
- **Kolejność kolumn:** inna niż w klasie. Najpierw `id` jako klucz główny, potem pozostałe
  kolumny alfabetycznie.


```text
Indexes:
    "patients_pkey" PRIMARY KEY, btree (id)
    "uk3usu2gl5shfee2u3f4gfw4w3p" UNIQUE CONSTRAINT, btree (id_card_no)
    "uka370hmxgv0l5c9panryr1ji7d" UNIQUE CONSTRAINT, btree (email)
```

Ograniczenia unikalności Hibernate dodaje osobnym `alter table ... add constraint`, więc musi
im nadać nazwę. Nie podaliśmy jej, dlatego ją wygenerował: prefiks `uk` (unique key) i skrót
(hash) z nazwy tabeli i kolumny. Ta sama tabela i kolumna dają zawsze tę samą nazwę. Nazwę
`patients_pkey` nadał PostgreSQL, bo w `create table` klucz główny jest bez nazwy.

## Zawężanie istniejącej tabeli

Zawężenie zadziałało bez kasowania wolumenu: po dodaniu `length` Hibernate przy starcie sam
zmienił typy istniejących kolumn. Udało się, bo żadna wartość w tabeli nie przekraczała nowych
limitów.

## Czego nie zrobi `ddl-auto=update`

Nie usunie kolumny ani tabeli: po usunięciu albo zmianie nazwy pola stara kolumna zostaje
w bazie razem z danymi.
